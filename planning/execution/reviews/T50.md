# Independent review — T50

Review **Prepare evidence-linked launch and portfolio material** in a different session/person from its implementation author. Read [the worker brief](../workers/T50.md), the canonical task, changed source, input contracts, fixture expectations and actual receipts. A green badge or implementation summary alone is insufficient.

**Expected purpose:** Capture silent short clip/full walkthrough from real release candidate, prepared-example labels and genuine own-file/export path. Write X/ShowHN draft and owner case study; record measured timings and any clip speedups. Do not publish/contact.

## Task-specific review

- Each launch claim has source commit/test receipt.
- clipped time labeled.
- no fabricated adoption/scores/manual contribution.
- no sensitive document in media.
- final direct-try/source/limits links supplied only after owner publishes.

Use fixture families F01, F03, F23 and invariants I06, I16, I18. Inspect a negative control and an error/partial path relevant to this task, not only a happy example.

```sh
python scripts/check_claims.py --surface launch && python -m unittest discover -s tests/docs -p test_launch_claims.py -v
```

## Scope and integrity

Check that implementation edits stay within `docs/launch/`, `artifacts/launch/`, `docs/case-study.md`, plus the common evidence-only namespaces. Verify approved shared leases, exact contract/dependency identities, complete attribution and no undeclared network or persistence. Reject deleted assertions, unjustified skips, refreshed baselines that hide failure, or tuning on held-out labels. No unrelated SaaS, repair or adjudication code.

## Required disposition

Write `artifacts/tasks/T50/review.md`: reviewed commit, reviewer/session identity, commands actually executed, test counts and skips, source/fixture/model identities, issues with severity and reproduction, and accept/request-changes/blocked. Explicitly label inspection-only areas. A material assertion without evidence is not accepted.

Use the task's proposal procedure for plan conflicts. The integrator repeats affected acceptance on the merge result; branch-local success does not certify integration. Preserve original bytes and rejected-experiment receipts. Rollback reverts candidate changes, never rewrites a baseline to erase a failure.
