# Interaction reference and visual verification

This is a **clickable design reference**, not the implemented browser PDF inspector. Its synthetic amount crop and native reading come from real generated bytes and the recorded native probe. File processing, the rest of the gallery and the finished browser engine remain implementation tasks. Prepared status, the named native renderer and unchecked automatic alignment stay visible.

Serve the package directory locally and open `reference/index.html`. The reference uses fixed relative assets and its prepared JSON report; it never accepts an arbitrary remote PDF URL. The Page / Reading / Compare controls, finding disclosure and privacy dialog are interactive. “See local-file flow” explains the specified flow rather than pretending to process a file. The export controls download the disclosed prepared reference evidence. This is not a production security boundary.

## What was executed

[The probe](../probes/reference_probe.py) exercised the owned HTML at 1440×1000, 390×844 and 320×844. It checked mode switching, tab keyboard behavior, Escape/focus return from the export dialog, reduced motion, initial visibility of the amount crop and controls, and absence of outer horizontal overflow. Its [receipt](../probes/results/reference-probe.json) contains exact environment and measured boxes.

Initial navigation to a localhost URL failed with `ERR_BLOCKED_BY_ADMINISTRATOR`. That policy was not disabled. The visual probe therefore used local DOM content with the owned CSS, image and prepared JSON inlined. It does **not** establish actual hosted asset loading, a network-privacy claim, PDF.js/Tesseract.js execution, or browser sandbox security. Chromium was run in this container with `--no-sandbox`; it was not a parser-isolation test.
