# Build log entry format

Use one entry per meaningful merged capability or experimental decision, not artificial daily updates. Entry fields: task/experiment, actual date and source commit, intended user outcome, hypothesis, what changed, exact commands and receipt paths, control/failure observed, owner intervention, reviewer, resulting decision, known limits and next dependency. Include a screenshot or small actual source-backed failure when useful; no private PDF content or secrets.

Example entry status: **not yet executed**. Intended first entry is T01 separate repository bootstrap and origin record. Its evidence must be the actual Git commit, bootstrap test output and original-repository no-change check; do not publish the planning document as if it were implementation history.
