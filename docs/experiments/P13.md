# P13 Experiment Report: Native RapidOCR Complement Evaluation (T44)

## Executive Summary
- **Experiment ID**: P13
- **Task ID**: T44 (pdf-t44)
- **Status**: `completed` (baseline measured; candidate blocked)
- **Disposition**: `blocked_missing_dependency_and_weights`
- **Recommendation**: Maintain Tesseract as the sole native OCR engine. RapidOCR remains `default_not_installed` due to unbundled ONNX weights and missing dependencies under offline containment.

## Evaluated Mechanisms
1. **Baseline**: Native Tesseract OCR (v5.5.3).
   - Evaluated across 8 development fixtures spanning F14 (`native-unicode`), F15 (`ocr-material`), and F16 (`adjacent-crop`).
   - Renders 2.0x rasters deterministically via PDFium and processes through local native CLI.
   - Captures real execution timings (~0.05s–0.12s per fixture), exact raster pixel dimensions, and raw OCR output.
2. **Selected Candidate**: RapidOCR v3.8.1 with PP-OCRv5 mobile English configuration (Source S47).
   - Package audit: `rapidocr` and `rapidocr_onnxruntime` are not installed in the native Python environment.
   - Weights audit: Official ONNX model weights (`ch_PP-OCRv4_rec_infer.onnx`, `ch_PP-OCRv4_det_infer.onnx`) are not pre-bundled in the repository checkout.
   - Containment policy: Runtime network downloading is strictly forbidden by repository offline security invariants.
   - Result: Concrete environment blocker recorded as `blocked_missing_dependency_and_weights` without fabricated execution or simulated 1/1 counts.
