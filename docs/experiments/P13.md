# P13 Experiment Report: Native RapidOCR Complement Evaluation (T44)

## Executive Summary
- **Experiment ID**: P13
- **Task ID**: T44 (pdf-t44)
- **Status**: `completed`
- **Disposition**: `candidate_evaluated_unintegrated` / `default_not_installed`
- **Recommendation**: Maintain native Tesseract as the sole production native OCR engine. RapidOCR v3.8.1 with PP-OCRv5 mobile English models was installed in an isolated experiment environment (`experiments/P13/.venv`), verified against trusted model digests, and executed across all 8 development fixtures. While functional and bounded to ~322 MB peak RSS (< 1 GiB budget), RapidOCR provides complementary recognition on complex raster text but requires ~43 MB of model weights and additional runtime dependencies. In accordance with the experiment contract, RapidOCR remains `default_not_installed` in the production native environment.

## Evaluated Mechanisms
1. **Baseline**: Native Tesseract OCR (v5.5.3).
   - Evaluated across 8 development fixtures spanning F14 (`native-unicode`), F15 (`ocr-material`), and F16 (`adjacent-crop`) from `fixtures/manifest.json`.
   - Renders 2.0x rasters deterministically via PDFium and persists raw PNG rasters into `artifacts/P13/rasters/` for durable verification.
   - Captures real execution timings (~0.05s–0.12s per fixture), exact raster pixel dimensions, and raw OCR output.
   - Nonzero exit codes, timeouts, and missing binaries are strictly preserved as terminal failures in the denominator.
2. **Selected Candidate**: RapidOCR v3.8.1 with PP-OCRv5 mobile English models (Source S47).
   - Isolated environment: `experiments/P13/.venv` (untracked, excluded via git exclude).
   - Packages: `rapidocr==3.8.1`, `onnx==1.22.0`, `onnxruntime==1.30.0`.
   - Model weights & trusted SHA-256 digests:
     - Detector: `ch_PP-OCRv5_det_mobile.onnx` (`4d97c44a20d30a81aad087d6a396b08f786c4635742afc391f6621f5c6ae78ae`)
     - Recognizer: `en_PP-OCRv5_rec_mobile.onnx` (`c3461add59bb4323ecba96a492ab75e06dda42467c9e3d0c18db5d1d21924be8`)
   - Strict model validation: `is_valid_onnx_model` parses protobuf field tags and wire types and verifies SHA-256 against expected digests. The junk-ONNX counterexample `b'\x08' + b'\x00' * 127` is strictly rejected as invalid protobuf wire format.
   - Inference execution: Real RapidOCR inference executed across all 8 development rasters, generating raw boxes, text lines, and line confidences.
   - Memory containment: Lazily initialized cached engine with `Det.limit_type = 'max'` and thread tuning limits peak RSS to ~322 MB (strictly < 1 GiB budget).
   - Invariant I17 (No consensus as truth): Candidate and baseline outputs are retained as separate observations; shared pixels are never conflated into synthetic ground truth.

## Architectural Conclusion
RapidOCR v3.8.1 with PP-OCRv5 mobile English was successfully proven in an isolated experiment environment with verified weights, robust protobuf validation, and bounded memory consumption. However, because native Tesseract already satisfies primary OCR requirements and avoids adding large model weights to the distribution, RapidOCR remains **default_not_installed** for production. The native Tesseract adapter continues as the sole production native OCR implementation.
