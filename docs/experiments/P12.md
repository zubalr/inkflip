# P12 Experiment Report: Secondary Browser PDFium Reader Evaluation (T43)

## Executive Summary
- **Experiment ID**: P12
- **Task ID**: T43 (pdf-t43)
- **Status**: `blocked` (candidate archive not bundled in repository; external network downloads forbidden by offline containment)
- **Disposition**: `blocked_missing_candidate_archive` / `default_unavailable`
- **Recommendation**: Maintain PDF.js as the sole primary browser reader. EmbedPDF PDFium remains default-unavailable in accordance with Invariant I13 and the P12 integration decision. The browser inspector core remains complete, standalone, and fully functional without secondary reader dependencies.

## Evaluated Mechanism & Candidate Inventory
1. **Baseline**: PDF.js plus Tesseract OCR.
   - Pinned and isolated reader adapter in `packages/readers-pdfjs` and `apps/web/node_modules/pdfjs-dist`.
   - Primary rendering and text extraction path across all supported browser surfaces.
   - Verified via Playwright headless Chromium harness (`experiments/P12/browser.spec.ts`): renders `white-contrast-control.pdf` onto HTML5 canvas, asserts non-blank ink pixels, and extracts text content (`$100`).
2. **Selected Candidate**: EmbedPDF PDFium release `v2.15.0` (Source S48).
   - Candidate archive: `pdfium-dist.tar.gz`.
   - Pinned release digest: SHA-256 `31cba71f5620bec3ae2aab6606f148e42cba0cd34d56cf5b54998d771e62bd42`.
   - Declared size: 2,661,637 bytes (< 24 MiB maximum chunk budget).
   - License / Rights: Apache 2.0 / PDFium terms (source S48).
   - **Offline Containment & Containment Policy**: The candidate archive is not pre-bundled in the repository. Invariant I13 / I14 prohibits runtime network fetching. Attempted intake via preparation command (`curl -fL -sS --max-time 15 -o artifacts/P12/pdfium-dist.tar.gz https://github.com/embedpdf/embed-pdf-viewer/releases/download/v2.15.0/pdfium-dist.tar.gz`) is blocked under offline execution.

## Counterexample & Integrity Audit Verification
Per review requirements, candidate presence alone does not imply acceptance:
1. **Missing Candidate**: Evaluated honestly as `status: "blocked"`, `disposition: "blocked_missing_candidate_archive"`.
2. **Corrupted / Tampered Candidate (Counterexample)**: Tested against a touched archive (size/digest mismatch) and corrupt tar archive. The verification logic in `check_manifest.py` verifies SHA-256, decompresses `tar.gz`, and validates the WebAssembly binary header magic (`\x00asm\x01\x00\x00\x00`). Tampered archives immediately produce `status: "blocked"`, `disposition: "candidate_rejected_integrity_mismatch"`, and are never falsely marked completed or accepted.
