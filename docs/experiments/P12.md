# P12 Experiment Report: Secondary Browser PDFium Reader Evaluation (T43)

## Executive Summary
- **Experiment ID**: P12
- **Task ID**: T43 (pdf-t43)
- **Status**: `blocked` (candidate archive not bundled; offline environment)
- **Disposition**: `blocked_missing_candidate_archive` / `default_unavailable`
- **Recommendation**: Maintain PDF.js as the sole primary browser reader. EmbedPDF PDFium remains default-unavailable in accordance with invariant I13 and the P12 integration decision. The browser inspector core remains complete and fully functional without secondary reader dependencies.

## Evaluated Mechanism & Candidate Inventory
1. **Baseline**: PDF.js plus Tesseract OCR.
   - Pinned and isolated reader adapter in `packages/readers-pdfjs`.
   - Primary rendering and text extraction path across all supported browser surfaces.
2. **Selected Candidate**: EmbedPDF PDFium release `v2.15.0` (Source S48).
   - Candidate archive: `pdfium-dist.tar.gz`.
   - Pinned release digest: SHA-256 `31cba71f5620bec3ae2aab6606f148e42cba0cd34d56cf5b54998d771e62bd42`.
   - Declared size: 2,661,637 bytes (< 24 MiB maximum chunk budget).
   - License / Rights: Apache 2.0 / PDFium terms (source S48).
   - **Offline Audit Result**: The candidate archive is not pre-bundled in the offline repository checkout. Strict environment containment policies prohibit runtime network fetching. Consequently, the candidate cannot be downloaded or compiled into WASM at runtime.

## Architectural Conclusion
The candidate reader `EmbedPDF PDFium` remains **default-unavailable**. Invariant I13 mandates that if a candidate is not accepted or its assets are unavailable, the default application must not depend on it or include secondary downloads in the public web bundle. Playwright verification confirms that `apps/web` contains zero EmbedPDF imports and functions independently with PDF.js as its primary reader.
