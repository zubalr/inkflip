# T05 proposal: decouple TEST-01 "no implementation" example from test:fixtures

Status: applied on `work/zcode/t05`, submitted for coordinator and independent
reviewer approval. Fallback if rejected: revert the `test:fixtures` registry
activation (keep `argv: null`) and leave registration to a later root-manifest
owner; the T05 planning acceptance commands do not use the registry, so T05
acceptance itself survives either outcome.

## Observed source

`tests/bootstrap/test_bootstrap.py` (`EmptyRegistrationFailsTests.
test_declared_suite_with_no_implementation_fails`, lines 91–95 at base 3bef697)
ran `task_acceptance.py run test:fixtures` and asserted it fails with
"no implementation registered".

`config/acceptance-commands.json` explicitly delegates the opposite step to
this task: the `test:fixtures` entry says "Implementation is registered by the
fixture owner; no runner is assumed." T05's fixture suite now exists, so the
fixture owner registered `test:fixtures` as `active` with
`python3 -m unittest discover -s tests/fixtures -v` (harness-unittest).

## Minimal reproducer

1. `git checkout work/zcode/t05` (or apply the registry edit on any checkout).
2. `bun run verify` → the T01 suite fails:
   `test_declared_suite_with_no_implementation_fails ... AssertionError: 0 == 0`
   because `run test:fixtures` now succeeds.

The T01 guarantee ("empty/missing test registration fails loudly") is intact
and still exercised; only its example command expired.

## Affected contracts / tasks / tests

- `tests/bootstrap/test_bootstrap.py` (T01-owned scope — the only out-of-scope
  edit on this branch; one test method).

## Recommended correction (applied)

Rewrite the failing example to use the same synthetic temporary registry the
sibling tests in that class already use: an `active` `harness-unittest` entry
with `argv: null` must still fail with "no implementation registered". The
guarantee no longer depends on another task's lifecycle state.
