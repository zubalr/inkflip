# T46 proposal: shared manual-receipt checker

## Observed source

T46's effective command is:

`node --test tests/parity/*.test.mjs && python scripts/check_manual_receipts.py compatibility`

The same command name is also T37 (`accessibility`) and T53 (`release`).
The original checker certified any receipt that had a few keys and a
nonempty `evidence` list on executed rows. Codex reproduced
`compatibility: ok (6 platforms)` at exit 0 while
`docs/compatibility/manual-receipt.json` had overall status `partial` and
marked Chromium, Firefox, WebKit and Linux amd64 unavailable.

## Minimal reproducer

```sh
python scripts/check_manual_receipts.py compatibility
python3 -m unittest discover -s tests/compatibility -v
```

## Shared format (for Devin / T37 / T53)

Keep schema_version `1.0.0`, `kind`, overall `status`, `host` identity and
`platforms[]` with `id`, `status`, `evidence`, and `identity` on executed
rows. Evidence paths are repository-relative real nonempty files, not
symlinks. Acceptance overall status must be `complete`. Required profile
ids are contract-derived, not whatever rows happen to be present:

- compatibility: `chromium`, `firefox`, `safari`, `linux-amd64-native`
- accessibility: `keyboard`, `amount-alternatives`, `zoom-400`,
  `reduced-motion`, `screen-reader-nvda-firefox`,
  `screen-reader-voiceover-safari`
- release: the union of the two lists (TEST-53)

`webkit-safari` does not satisfy `safari`. `pdfjs-node-wrapper` does not
satisfy a browser profile. Previous Chromium, Firefox ESR and previous
Safari majors from PERFORMANCE_AND_COMPATIBILITY.md still need an explicit
T53 receipt shape; this checker treats current-family coverage as the T46
bar.

Optional reporter (does not certify):

```sh
python scripts/check_manual_receipts.py compatibility --inventory
```
