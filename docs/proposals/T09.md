# T09 proposal: record F10/F11 fixture absence and substitute coverage

Status: informational, submitted for coordinator and independent reviewer
approval on `work/devin/t09`. No code or contract change is requested; this
records a coverage gap between the T09 task contract and the T05 fixture
tree, and how the suite handled it without fabrication.

## Observed source

The effective T09 contract (`python3 scripts/coordination.py task T09`)
lists `fixture_ids: [F01, F02, F07, F08, F10, F11]`.

The T05-generated fixture tree contains no F10/F11 artifacts:

- `fixtures/public/` — F01 mapping-amount + control, F02 covered-amount +
  control, F07 geometry-{0,90,180,270} + control.
- `fixtures/development/` — F08 userunit-{0.5,1,2,10}, F03 scan family.
- `fixtures/manifest.json` records no F10/F11 entries; the generator
  (`scripts/make_fixtures.py`) emits only F01/F02/F03/F07/F08 recipes.
- F10 (mapping-missing) and F11 (duplicates) exist only as
  planning/catalog examples, not generated PDFs.

## Minimal reproducer

```sh
ls fixtures/public fixtures/development | grep -E "mapping-missing|duplicates"
# -> no output; the suite asserts the same and fails if they appear.
```

## How T09 covered it without fabricating

- `tests/readers/pdfjs.spec.ts` "F10/F11 absent from T05 tree; ordinal
  identity preserves duplicates" asserts the files are absent (so the gap
  stays visible instead of silently passing), and verifies the F11
  mechanism — `occurrenceId` binds (run_key, reader, page, ordinal,
  locator), so equal strings at different ordinals remain distinct
  occurrences.
- F10's "absent mapping" genus is partially adjacent to F02's covered
  early string: the adapter preserves whatever `getTextContent` emits,
  including strings with no painted counterpart.
- `artifacts/tasks/T09/receipt.json` and `handoff.json` record the
  limitation explicitly; no fixture, extraction or count was invented.

## Affected contracts / tasks / tests

- T09 acceptance criteria are all met with generated fixtures; the F10/F11
  gap reduces fixture-family coverage only.
- Recommended owner action: T05 (fixture owner) generates F10/F11 in a
  later pass, or the coordinator narrows T09's `fixture_ids` — either
  way, `tests/readers/pdfjs.spec.ts` will detect their arrival (the
  absence assertion flips and should be replaced with real coverage).

## Alternatives considered and rejected

- Generating F10/F11 inside T09: fixture generation is T05's owned scope;
  duplicating it would fork the generator contract.
- Skipping silently: hides a named-contract coverage gap.
- Writing `review.md` or claiming acceptance worker-side: review and
  acceptance belong to the independent reviewer and coordinator.
