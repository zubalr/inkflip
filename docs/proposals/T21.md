# T21 — scope record: root-composition lease and fixture-set deviation

Recorded by the integrator after independent review (reviewer
`independent-explore`, round 1). Both items are documented here per the
plan-mismatch rule; the implementation itself is unchanged.

## 1. Root-composition lease

T21's frozen `allowed_scope` covers `apps/web/public/examples/`,
`fixtures/public/`, `scripts/prepare_examples.py`, `tests/gallery/`,
`apps/web/src/features/gallery/`. The delivered gallery additionally
touches three root-composition files, which `planning/execution/
OWNERSHIP.md` reserves for T01/T13/T48 with "later gallery, cache and
documentation integrations use an explicit composition lease":

- `apps/web/src/App.tsx` — parses `#/workspace?example=<id>` (charset
  `[a-z0-9-]+`) alongside the existing `?example=true` route flag.
- `apps/web/src/pages/Home.tsx` — mounts `ExamplesGallery` and passes an
  `onOpenExample` handler that navigates to the workspace route.
- `apps/web/src/pages/Workspace.tsx` — new optional `initialExampleId`
  prop; when set, the committed report is fetched and run through the
  real `session.offerFile` import gate (never mounted directly); an
  honest `role=alert` surface reports fetch failures.

**Lease rationale:** a public gallery cannot deliver "open this report"
without an entry seam. The edits are additive-only (new optional prop,
new route parameter, new section on Home), preserve every existing flow
(`?example=true` → `EXAMPLE_DOC`; `#/workspace` → empty; the default
`exampleDoc` condition is unchanged), and are verified by
`tests/gallery/smoke.spec.ts` plus the T13/T16/T17 regressions that
exercise the same files.

**Decision:** accepted as the T21 composition lease. The seams are
minimal and required; no alternative within the frozen scope can mount
the gallery.

## 2. Fixture-set deviation

The plan named standalone cards `F01, F03, F04, F07, F12, F14`. The
shipped set is `F01, F02, F03, F07, F11, F12`, with F04 and F14 carried
as executed companion variants:

- `amount` (F01): `unicode_native`/`unicode_control` are F14's PDFs —
  the native-unicode mechanism is a variant of the same ToUnicode
  family.
- `covered` (F02): `contrast_white`/`contrast_control` are F04's PDFs —
  the white-contrast mechanism is a variant of paint-over occlusion.

F02 (covered text) and F11 (duplicate/repeated candidates) were promoted
to standalone cards because their mechanisms are genuinely distinct —
which serves the "gallery not padded with repetitive cases" criterion
better than two near-duplicate standalone cards would.

**Every planned fixture still ships with executed evidence**: all six
planned fixture PDFs appear in manifests with sha256 bindings and real
captured reports (F04 → `covered/report.contrast-*.json`, F14 →
`amount/report.native-unicode-*.json`). No fixture was dropped or
replaced by a synthetic stand-in.

**Decision:** accepted. The deviation strengthens the no-padding
criterion while preserving every planned fixture as executed evidence.
