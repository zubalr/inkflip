# T27 — owned geometry API decision: `canonical_to_raster`

Status: implemented on `work/zcode/t27` (wave-2 revision round, 2026-09-12).
Owner: T27 worker (ZCode) under coordinator approval; F10 coordinator decision
approved this direction. No shared schema, frozen planning file, or other
task's module is changed by this document or the accompanying code.

## Decision

The native Tesseract adapter authorizes precise OCR geometry through an
**optional, owned `render_meta.canonical_to_raster` entry**: the six-component
affine `[a,b,c,d,e,f]` (x' = a*x + c*y + e, y' = b*x + d*y + f, per
`planning/architecture/COORDINATES.md`) that maps canonical page points to the
raster pixels of the recorded named render. For a recorded render this is

```
canonical_to_raster = Scale(s) * R
```

with `s` the raster scale (px per physical point) and `R` the quarter-turn
rotation matrix for clockwise rotation in top-left canonical space. It is
**not** `P = Scale(s) * R * C`: the user-space compensation `C` must not be
applied twice; the matrix starts from canonical space.

## Rules enforced by the adapter

1. **Validation and snapshot at open.** `open_raster` validates a recorded
   matrix (exactly six components, all finite non-bool numbers), derives its
   inverse once via `inkflip.contracts.inverse`, and round-trips the four
   raster corners through inverse and forward. Requirements: finite inverse;
   recovered canonical coordinates finite and bounded (|coord| <= 1e9, which
   also rejects extent-amplifying near-singular transforms); round-trip error
   <= 1e-5 physical points scaled to pixels. Any violation is a typed
   `geometry_unavailable` refusal at open — an explicitly invalid matrix never
   degrades to the scalar path.
2. **Scale alone is a diagnostic.** The legacy
   `raster_scale_px_per_pt` scalar is retained for provenance reporting but
   never authorizes geometry: without a matrix, occurrences carry verbatim raw
   text with `unknown` precision and a null polygon (I04).
3. **Provenance wins.** `plan_crop` snapshots the handle's inverse into the
   `CropPlan` (appended optional field, positional construction preserved).
   A caller-built `CropPlan` may pass an inverse only if it matches the
   handle's validated snapshot exactly; a stale or invented inverse is refused
   with `geometry_unavailable` and never silently replaced.
4. **Effective resize inversion.** Pillow rounds destination dimensions, so
   the adapter records `effective_resize = (dest_width, dest_height) /
   (source_width, source_height)` from the ACTUAL integer output dimensions
   and inverts with exactly those factors. Requested factors stay recorded on
   the plan for provenance.
5. **Output budget before allocation.** Destination dimensions are computed
   and bounded (`<= 40 Mpx`, finite products) before Pillow `resize` is
   called; excessive upscale is a typed `resource_limit`. This is
   adapter-owned pre-subprocess allocation, distinct from T29 supervision.
6. **Quad mapping.** All four OCR box corners are mapped individually:
   effective-resize inverse, padded-crop offset, then the recorded render
   inverse. The polygon keeps the quad; a two-corner axis-aligned
   reconstruction would misplace sheared or rotated content.
7. **Transform identity.** Occurrence `transform_ids` record
   `["ocr-crop-inverse", "canonical-render-inverse"]` on the matrix path.
   Rounding stays at 6 decimal places with negative zero normalized; no
   NaN/Infinity JSON leaves the adapter.

## Test evidence (stub/tiny-render only)

* COORDINATES numeric example: canonical (56,340) at R90/scale 1.5 ->
  raster (540,84); crop offset (500,60), resize 2 -> OCR (80,48); inversion
  recovers (56,340) with all four corners asserted.
* Four rotations (0/90/180/270) over tiny real named renders; the actual
  rotation direction is established per render by exact pixel comparison
  against PIL rotations of the unrotated bitmap (independent anchor), and the
  recorded matrix maps a stub-OCR box back to the analytic canonical quad.
* One shear case proving the quad is not rebuilt as an axis-aligned box.
* Scale-only / absent metadata -> `unknown` geometry with raw text retained.
* Invalid, singular, nonfinite, non-numeric, and extent-unstable matrices ->
  typed `geometry_unavailable`; caller provenance mismatch -> typed refusal.
* Odd 101x51 -> 50x26 resize verified against the real saved PNG dimensions
  read by a stub engine, including the crop offset.
* Pre-allocation budget: (1000,1000) and 1e300 factors on a tiny crop return
  `resource_limit` with `resize` provably never called.

Final OCR rerun on the ultimate candidate remains pending the heavy-slot
return and is recorded honestly in the task handoff.
