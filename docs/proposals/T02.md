# T02 proposal — contract interactions needing owner/coordinator action

Two plan↔implementation mismatches observed while executing T02 at base
3bef697a31120d4cb32e8fa044d419bc34e32cf5. Neither blocked the T02 deliverables;
both need a decision outside this task's allowed scope.

## P1 — `.github/workflows/ci.yml` cannot be SHA-pinned from inside T02

**Observed.** `planning/execution/tasks.json` T02 purpose says "Pin compatible
patched toolchain builds and full action SHAs", and the workflow file itself
comments "T02 replaces them with reviewed commit SHAs before this workflow is
hardened". But the effective T02 `allowed_scope` (tasks.json +
`execution/overrides.json`) covers only the lock/manifest/toolchain surfaces —
`.github/` is not writable by T02.

**Minimal reproducer.** `git check-ignore` n/a — the file exists and uses
`actions/checkout@v4` (a mutable major tag). Editing it exceeds the contract
scope; skipping it leaves a mutable action reference in CI.

**What T02 did instead.** `build/base-image.lock.json` records the immutable
resolution (`actions/checkout@v4` → `11d5960a326750d5838078e36cf38b85af677262`,
tag `v4` == `v4.4.0`, via `git ls-remote`), and
`scripts/check_dependencies.py --frozen` now *fails* if any workflow `uses:`
reference lacks a recorded full-SHA — so a new unpinned action breaks the T02
acceptance command immediately.

**Recommended delta.** Either (a) extend T02 scope to
`.github/workflows/ci.yml` so the pin lands in-file, or (b) assign the one-line
edit (`uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262  # v4.4.0`)
to the surface's owner. check_dependencies keeps verifying the record either
way.

## P2 — T01 bootstrap assertion is stale after T02 installs Playwright

**Observed.** `tests/bootstrap/test_bootstrap.py::
test_declared_suite_with_missing_runner_fails` asserts
`task_acceptance.py run test:browser` fails with "prerequisites missing".
T02 is *required* to install the resolved Playwright (test:browser's
`requires: node_modules/.bin/playwright`, owner_task T02). With the runner now
installed, the command still fails honestly — playwright collects zero tests —
but with a different message, so the T01-owned assertion fails.

**Minimal reproducer.** `bun install --frozen-lockfile && python3 -m unittest
discover -s tests/bootstrap -v` → 1 failure (that test only; 48 pass).

**Why this is not a weakened guarantee.** The invariant "declared commands
fail explicitly until their suite lands" still holds: `test:browser` exits
nonzero with "zero tests collected — empty required suites fail". The
equivalent live scenario for a still-missing prerequisite is `test:visual` /
`test:a11y` / `test:privacy` (their `tests/<name>/` dirs do not exist yet).

**Recommended delta.** T01-scope file; the owner should repoint the assertion
at a still-declared command (e.g. `test:visual`) or assert "fails explicitly"
without pinning one stderr string. T02 does not edit another task's tests.

**Affected.** tests/bootstrap (T01), test:browser registration (T02), the
`verify` group total.

## P3 — declared `test:native` now reaches pytest but collects frozen planning files

**Observed.** `config/acceptance-commands.json` registers
`test:native` as `uv run --frozen --project native python -m pytest` with
`requires: native/uv.lock`. Before T02 the command was blocked on the missing
lock; T02 lands the lock, so the command now executes. Run from the repo root,
pytest rootdirs at the root (no ini file there) and recursively collects
`planning/tools/test_validators.py`, which imports `yaml` — a planning-tool
dependency that is deliberately not a product dependency — and errors.

**Minimal reproducer.** `uv sync --project native && uv run --frozen
--project native python -m pytest` → collection ImportError on
`planning/tools/test_validators.py`.

**Why this is honest.** The command is still `status: declared`; it fails
explicitly until its suite lands, which is the intended contract. But the
failure mode (collecting byte-frozen planning modules) is an accident of
argv shape, not a designed gate.

**What T02 did.** `native/pyproject.toml` gained
`[tool.pytest.ini_options] testpaths = ["tests"]`, which scopes collection
correctly whenever pytest runs with `native/` as rootdir (e.g.
`cd native && uv run pytest`). This cannot fix the repo-root invocation
because rootdir selection happens before that file is consulted.

**Recommended delta.** The native test task that lands the suite should
either (a) update the registered argv to `uv run --frozen --directory native
python -m pytest`, or (b) add a root-level pytest ini confining collection to
`native/tests`. Both touch registry/root config outside T02 scope.

## P4 — cancellable Tesseract initialization (Astra scope decision, 2026-09-12)

Independent T10 review reproduced a hidden worker lifetime in tesseract.js
7.0.0: `createWorker` starts the transport immediately but returns its handle
only after initialization. A stalled initializer cannot be stopped through
the public API. Initialization rejection can also leave readiness unresolved.
T11 emits termination intents; the embedder still needs a cancellable transport.

Astra owns the repair under `pdf-ebz`. The maintained Bun patch adds an optional
`WorkerOptions.signal` to the existing Promise-returning constructor. Abort
rejects readiness and posted jobs, prevents later job dispatch and terminates
the owned transport synchronously. Initialization rejection and worker errors
release the transport too. Normal initialization and recognition retain the
existing Tesseract protocol. Reader deadlines and operation identity remain T10.

The upstream URL, Blob/FileReader and canvas input loaders remain outside this
patch. Aborting a worker does not settle a `recognize` call still awaiting one
of those loaders. The owned T10 port accepts prepared `Uint8Array` PNG bytes;
it materializes those bytes inside its bounded reader operation before calling
the engine. The byte path performs no asynchronous fetch/FileReader work, and
the constructor prevents dispatch if cancellation occurs before its microtask.

Bundle the declared `apps/web` dependency's source entry. The upstream prebuilt
client `dist/tesseract.esm.min.js` does not contain this patch and must not be
used by the application or its acceptance harness. The staged worker, WASM cores,
model, their hashes and their Apache-2.0 notices are unchanged.

`config/dependency-patches.json` records upstream and patched source hashes,
the patch hash, origin and license. Frozen verification checks the installed
constructor/types, exact version and matching package/lock declarations. T02's
scope now includes this record and `patches/`, so later patch changes invalidate
its acceptance. Bun installs the committed patch on both hosts; do not edit a
shared cache or rely on an unrecorded `node_modules` change.

Primary sources: [pinned constructor](https://github.com/naptha/tesseract.js/blob/v7.0.0/src/createWorker.js)
and [Bun patch workflow](https://bun.sh/docs/pm/cli/patch). Verification uses the
installed constructor, controlled transports, and actual browser workers whose
independent activity must stop on abort. See `artifacts/tasks/T02/cancellation-patch/`.
